## Layout

| Path | Purpose |
|---|---|
| `bootstrap/` | One-time Terraform: remote state, federated identity and [[cicd_label]] repository wiring. |
| `infra/` | [[iac_label]] for the Azure ML workload, one parameter file per environment ([[environments_csv]]). |
| `src/` | Training code (prep, train, evaluate and register). |
| `mlops/azureml/` | Azure ML data, environment, pipeline and endpoint definitions. |
| `mlops/azureml/components/` | One Azure ML command component for each pipeline step (prep, train, evaluate and register), with typed inputs and outputs. The pipeline calls them by name. |
| `[[pipelines_dir]]/` | CI/CD definitions. |

If you listed several `workloads` in the inputs file, the platform (`bootstrap/`, `infra/`) is rendered once and each workload gets its own `workloads/<name>/` folder with `src/` and `mlops/`. The pipeline files keep their folder and get a `-<name>` suffix.

## Phases

Deploy in order and stop after any phase to review. Each environment ([[environments_csv]]) is gated by its [[cicd_label]] environment approval.

| Phase | What | How | Stop and check |
|---|---|---|---|
| 0. Platform prerequisites | Network, DNS and Log Analytics owned by a platform team (scenarios 4 and 11, and private modes) | Outside this repo; see the scenario notes below | Private endpoints reachable from your agents |
| 1. Bootstrap | Remote state, federated identity, [[cicd_label]] wiring | `cd bootstrap && terraform init && terraform apply '-var-file=bootstrap.tfvars'` (or the accelerator with `-Deploy`) | Identities and environments exist |
| 2. Infrastructure | Azure ML workspace and dependencies | Push and merge to `main`. The `infra` pipeline deploys the first environment, then waits for approval before the next | Workspace is healthy in each environment |
| 3. Workload | Data asset, training, evaluation, registration | Run the `ml-train` pipeline for an environment | Model registered; metrics acceptable |
| 4. Serve | Endpoint deployment, and promotion across environments for the registry scenario | Run `ml-deploy` and, for the registry scenario, `ml-promote` | Endpoint scores a sample request |

The pipelines are named with their phase number so they sort in run order.

and Microsoft-hosted agents cannot reach them. Before using `ml-train` and `ml-deploy`, run the pipelines on self-hosted agents that can reach the private
endpoints, or temporarily allow the IP address of your agent.
